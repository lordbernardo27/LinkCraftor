   13: # ---------------------------------------------------------------------------
   14: # Design notes (what changed and why)
   15: #
   16: # The previous implementation kept a module-level list (_queue_job_ids) that
   17: # was rebuilt from the job store on every call via refresh_queue_from_store().
   18: # Because the store was always authoritative, the list carried no information
   19: # of its own — but it created two real problems:
   20: #
   21: #   1. NON-ATOMIC DEQUEUE: dequeue_job() removed a job from the local list
   22: #      while its status in the store remained "queued" until the worker later
   23: #      called mark_job_running(). Any concurrent worker (thread OR separate
   24: #      process) refreshing from the store in that window would re-discover the
   25: #      job and dequeue it again -> duplicate processing.
   26: #
   27: #   2. STATE DRIFT: two sources of truth that had to be defended against each
   28: #      other in multiple places (dead "clear()" branch, redundant existence
   29: #      checks, 2-3 load_jobs() calls per operation).
   30: #
   31: # This version deletes the in-memory list entirely. The job store IS the
   32: # queue: a job is "queued" iff its persisted status is JOB_STATUS_QUEUED.
   33: # dequeue_job() now CLAIMS the job atomically — it transitions the job to
   34: # JOB_STATUS_RUNNING inside a cross-process lock before returning it — so a
   35: # job can be handed to exactly one worker. This also means the queue trivially
   36: # survives process restarts: anything persisted as "queued" is picked up.
   37: #
   38: # Ordering is unchanged: ascending (priority, created_at) — i.e. LOWER
   39: # priority number is served first, ties broken oldest-first (FIFO). job_id is
   40: # appended as a final tie-breaker so ordering is fully deterministic.
   41: # ---------------------------------------------------------------------------
   42: 
   43: # Cross-process lock file guarding the dequeue critical section
   44: # (read store -> pick job -> flip status). Lives next to this module by
   45: # default; override with ORCHESTRATION_QUEUE_LOCK_PATH if the package
   46: # directory is read-only in your deployment.
   47: _LOCK_PATH = Path(
   48:     os.environ.get(
   49:         "ORCHESTRATION_QUEUE_LOCK_PATH",

   54: # In-process lock: cheaper than the file lock for threads within one process,
   55: # and required anyway because fcntl/msvcrt locks are per-process, not
   56: # per-thread.

  131:
