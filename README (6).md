# LinkCraftor AK.6 — Four Remaining Trust Controls, Combined Inactive Patch

This is **one installation batch** for independent worker-token authentication, a protected issuer trust anchor, durable replay/revocation, and an explicit administrator-controlled issuer onboarding procedure. It does not enable queue claims, workers, or six queued jobs.

## Installation — development PC (PowerShell at LinkCraftor root)

Copy `ak6_operational_trust.py`, `apply_ak6_four_controls.py`, and `test_ak6_four_controls.py` together into the project root. Run:

```powershell
$ErrorActionPreference = 'Stop'
python .\test_ak6_four_controls.py
if ($LASTEXITCODE -ne 0) { throw 'AK.6 tests failed' }
python .\apply_ak6_four_controls.py
if ($LASTEXITCODE -ne 0) { throw 'AK.6 combined installation failed' }
```

* The installer requires the previously installed signed-grant and persisted-lease verifiers. It patches only `ak6_signed_execution_grants.py`, `universal_runtime_registration.py` and creates the `ak6_operational_trust.py` module. Original source is backed up under `backend/server/data/runtime_backups`. It will refuse unknown code versions, partial installations and modified guards. The queue, feature flags, workflow scope and persisted lease source are not changed.
* The patch remains **inoperative for production** without a dedicated Windows worker account and an externally issued signer key. This is fail-closed by design.
* In the existing call graph, the queue **reserves** a signed nonce inside the lock, the outer `execute_registered_runtime_job_v1` checks an existing reservation and binds its persisted lease, and the nested `dispatch_registered_runtime_handler` **consumes** the nonce before the actual handler. Reuse and revocation are denied. If a queue mutation fails after reservation, issue a fresh grant; do not reset the ledger as a workaround.

## External provisioning — a separate privileged operation

1. An organization-controlled issuer must already exist. **Generate and retain the Ed25519 private signing key outside the worker host**, ideally in a restricted KMS/HSM-backed signing service; protect its grant issuance policy. No private key is included or generated by this package.
2. Provision a **dedicated, non-interactive Windows service identity** and run the Universal Runtime Worker under that identity. Verify the actual Windows process token and service configuration. Do not authorize an interactive developer account as the worker.
3. An administrator on the worker host may run:

   ```powershell
   .\provision_ak6_machine_trust.ps1 -WorkerAccount 'DOMAIN\LinkCraftorWorker' -PublicKeyB64File 'C:\secure-staging\issuer_public.b64'
   ```

   The script refuses overwrite, pins the issuer's 32-byte public key under `C:\ProgramData\LinkCraftor\AK6\authority`, pins the dedicated worker token SID, and restricts ACLs. The signer **private** key must never be put on this host. The state directory receives access only for the dedicated worker and administrators.
4. The existing signed-grant verifier still expects `LC_AK6_AUTHORITY_PUBLIC_KEY_B64` and `LC_AK6_SIGNED_JOB_GRANTS_JSON` from the deployment mechanism; the new operational gate compares the supplied public key to the **OS-protected machine-pinned key** before any grant action. Provision and rotate grants through your controlled deployment; the worker must not issue its own grants.
5. `revoke_ak6_grant.py --nonce <nonce>` is a privileged break-glass command that durably marks a nonce as revoked, including tombstoning previously unseen grants. The ledger is the shared single-host SQLite database under the protected state path; it must be on reliable local storage, not a network share. Multi-host deployment requires a *shared transactional* ledger instead and is **not certified** by this package.

## Security limits / candid certification status

* The isolated tests use synthetic SID and temporary data paths. They **do not** establish a real privileged Windows worker service, operational ACLs, a protected signing issuer, or tested job execution. These are **operator/deployment prerequisites**, not something a chat script can safely assert.
* The existing Ed25519 grant schema binds canonical job, workspace, workflow, stage, handler registration, worker ID, validity and nonce. The protected worker SID is independently compared to the process token; a deployment must ensure the dedicated account cannot be interactively impersonated.
* The SQLite reservation is at-most-once authorization for the single canonical protected path, **not** exactly-once completion of side effects. Lease and job statuses remain enforced by the earlier persisted-lease integration. Worker restart/recovery/reissued grants must be tested under AK.7 before production.
* OS ACL checks and service identity behavior have not been run on this Linux packaging environment; test them on Windows. If they do not work, keep production NO-GO. Administrative compromise remains a trust-boundary limitation.
* The signed verifier still supports an isolated test environment: **never** interpret test signing keys, synthetic worker identities or current user account as production authority. Do not enable `runtime_queue_claims_enabled` or start the worker from this package.
