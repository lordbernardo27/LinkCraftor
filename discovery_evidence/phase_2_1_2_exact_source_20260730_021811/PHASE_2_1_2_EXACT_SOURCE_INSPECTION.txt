00015: #
00016: # The previous implementation kept a module-level list (_queue_job_ids) that
00017: # was rebuilt from the job store on every call via refresh_queue_from_store().
00018: # Because the store was always authoritative, the list carried no information
00019: # of its own — but it created two real problems:
00020: #
00021: #   1. NON-ATOMIC DEQUEUE: dequeue_job() removed a job from the local list
00022: #      while its status in the store remained "queued" until the worker later
00023: #      called mark_job_running(). Any concurrent worker (thread OR separate
00024: #      process) refreshing from the store in that window would re-discover the
00025: #      job and dequeue it again -> duplicate processing.
00026: #
00027: #   2. STATE DRIFT: two sources of truth that had to be defended against each
00028: #      other in multiple places (dead "clear()" branch, redundant existence
