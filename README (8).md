# LinkCraftor AK.6 - combined Windows operational provisioning

This single script **stages** all remaining machine-provisioning components without starting a worker or running a job:

1. Registers a dedicated, **disabled** Windows service under a virtual service account (`NT SERVICE\\<ServiceName>`), reusing an independently supplied and reviewed SCM-compatible signed service executable.
2. Validates an independently verified SHA-256 fingerprint of an **external issuer's Ed25519 public key**, then pins that public key under `C:\ProgramData\LinkCraftor\AK6\authority`.
3. Pins the service account's Windows SID under the same protected directory.
4. Provisions `C:\ProgramData\LinkCraftor\AK6\state` with a restrictive ACL for the existing durable nonce ledger. The worker account can modify only the state directory, not the issuer key.
5. Validates service registration, configured identity, ACLs and pinned bytes, and produces a single JSON report.

The script runs the **existing 28 isolated AK.6 tests** first. It also rejects pre-existing services or machine-trust directories rather than overwriting them, and attempts rollback of new resources on failure.

## Required real inputs (not generated by ChatGPT)

- A reviewed **Windows Service Control Manager-compatible worker service executable**, signed and securely installed in a non-user-writable directory. A `python.exe` invocation or `.py` script by itself is **not** an SCM-compatible service executable. The executable must be deliberately configured to host LinkCraftor's **existing** worker and must not process live jobs until the later controlled activation gate.
- SHA-256 of that executable, independently approved after review.
- The base64-encoded, **32-byte Ed25519 public key** from the real external authorization issuer (never a private key or test key).
- The SHA-256 fingerprint of the **raw public-key bytes**, checked out-of-band with the issuer/operator rather than taken solely from the same downloaded file.

The script is not a signing-key generator, issuer implementation, or Windows worker service executable. Without these inputs it **will not** register a service or provision trust files.

## Run once in elevated Windows PowerShell 5.1 or 7

Extract `AK6_Combined_Provision_And_Verify.ps1` into the LinkCraftor project root. In an **administrator** PowerShell window at that root, run:

```powershell
$ErrorActionPreference = 'Stop'
Unblock-File .\AK6_Combined_Provision_And_Verify.ps1
.\AK6_Combined_Provision_And_Verify.ps1 `
    -ServiceName 'LinkCraftorAK6Worker' `
    -ServiceBinary 'C:\Program Files\LinkCraftor\WorkerService\LinkCraftorWorkerService.exe' `
    -ApprovedServiceBinarySha256 '<verified-64-character-exe-sha256>' `
    -IssuerPublicKeyFile 'C:\secure\issuer_ed25519_public.b64' `
    -ApprovedIssuerKeySha256 '<verified-64-character-raw-public-key-sha256>'
```

Paths and hashes above are **placeholders**, not assertions that you have these files. Do not use fake values. The executable must be validated as a true service executable; registration alone does not prove it can operate as a service or invoke the existing worker safely.

## Results and remaining gate

Report: `AK6_COMBINED_PROVISION_REPORT.json` in LinkCraftor root.

A successful report certifies **machine configuration only**. It deliberately marks these further checks `BLOCKED`:

- Actual service-token attestation under a running but non-claiming worker service.
- Verification of a **real issuer-signed grant**, not a synthetic test grant.
- AK.7 isolated integrated certification, including actual service identity, nonce lifecycle, live lease validation, restart/revocation and all six stages.

**No production authorization or AK.7 certification is claimed. Worker service stays disabled and no production claims or handlers are run.**

### Windows scripting compatibility

The `.ps1` is saved with a UTF-8 BOM, and all code text uses ASCII punctuation to avoid the Windows PowerShell 5.1 encoding failures encountered earlier.

### Security limitations and operator responsibility

The SHA-256 values and signing service binary must come from independently established, trusted operator sources. A valid Authenticode signature alone does not establish that an executable is the correct LinkCraftor worker service. ACL protection against unprivileged users does not protect against compromise of Windows Administrators/SYSTEM. The provisioned nonce-state directory is not by itself a cross-process restart certification. Do not copy this Windows development identity design unchanged to AWS Linux; use the production environment's workload identity and key management services when the deployment is designed.
