# LinkCraftor API Inventory

## Document Control

Architecture: Platform Security Architecture
Phase: 3 - Asset Inventory & Attack-Surface Management
Component: 3.1.6 API Inventory
Version: 1.0.0
Status: Active Security Architecture
Architecture ID: platform-security-architecture

## 1. Purpose

This component establishes the persistent security inventory of LinkCraftor
APIs and endpoints.

It does not create a replacement API routing system.

## 2. Existing API Authority

The FastAPI application remains authoritative for operational API routing.

Canonical operational sources include:

- backend/server/main.py
- FastAPI app.routes
- FastAPI OpenAPI metadata

The security inventory must consume this operational API state rather than
redefine it.

## 3. Relationship

FastAPI Application
→ Runtime Route Table / OpenAPI
→ PSA 3.1.6 Security API Inventory

## 4. Security Inventory Responsibility

PSA 3.1.6 adds persistent security-management metadata including:

- stable security API identity.
- HTTP methods.
- path.
- route name.
- tags.
- application references.
- service references.
- exposure metadata.
- authentication metadata.
- authorization metadata.
- ownership references.
- lifecycle status.
- evidence.
- source provenance.

## 5. Canonical API Record

Every API record must contain:

- security_api_id.
- path.
- methods.
- route_name.
- environment.
- status.
- source.
- architecture_id.
- component_id.
- first_seen_at.
- last_seen_at.

Optional metadata may include:

- tags.
- application_reference.
- service_reference.
- product_reference.
- company_reference.
- owner_reference.
- technical_owner_reference.
- security_owner_reference.
- authentication_required.
- authorization_required.
- internet_exposed.
- internal_only.
- deprecated.
- version_reference.
- openapi_operation_id.
- response_model_reference.
- evidence.
- notes.

## 6. Identifier

Canonical API security identifiers use:

SEC-API-XXXX

The security identifier does not replace FastAPI route identity.

## 7. Status

Canonical statuses are:

- discovered.
- active.
- inactive.
- deprecated.
- unauthorized.
- quarantined.
- decommissioning.
- decommissioned.

## 8. Environment

Canonical environments are:

- development.
- testing.
- staging.
- production.
- shared.
- internal.
- unknown.

## 9. Runtime Route Bridge

The security inventory may ingest FastAPI app.routes.

Runtime-derived data may include:

- path.
- methods.
- route name.
- tags.
- operation metadata.

The bridge must never mutate FastAPI routes.

## 10. OpenAPI Relationship

OpenAPI remains an operational representation generated by FastAPI.

PSA 3.1.6 may use OpenAPI metadata as evidence.

The PSA inventory does not replace OpenAPI.

## 11. Application Boundary

Application identity remains governed by 3.1.4.

An API may reference an application.

## 12. Service Boundary

Service and microservice identity remains governed by 3.1.5.

An API may reference a service.

## 13. Ownership Boundary

Ownership references may be stored here.

Authoritative ownership assignment remains 3.1.16.

## 14. Criticality Boundary

Known criticality metadata may be preserved.

Authoritative Asset Criticality Classification remains 3.1.17.

## 15. Shadow API Boundary

This inventory records known APIs.

Shadow API Detection remains governed by 3.1.15.

## 16. Internet Exposure Boundary

Known exposure metadata may be stored.

Authoritative Internet-Exposed Asset Discovery remains governed by 3.1.13.

## 17. Security Requirements

3.1.6 must:

- preserve stable SEC-API identity.
- preserve FastAPI path and methods.
- preserve route name.
- support route-table ingestion.
- preserve first-seen timestamps.
- persist API inventory.
- support environment filtering.
- support lifecycle status.
- identify unauthorized APIs.
- identify deprecated APIs.
- never mutate FastAPI routes.
- integrate with the Central Architecture Registry.

## 18. Sensitive Information

The inventory must not contain:

- passwords.
- bearer tokens.
- private keys.
- API secrets.
- session credentials.
- raw authentication secrets.

## 19. Completion Boundary

3.1.6 establishes API Inventory capability.

It does not claim:

- complete authentication-policy enforcement.
- complete authorization-policy enforcement.
- shadow API detection.
- internet-exposure discovery.
- API vulnerability scanning.
- API abuse protection.
- ownership certification.
- criticality certification.
- complete attack-surface certification.

## 20. Completion Statement

This component establishes the persistent security API inventory while
preserving FastAPI as the authoritative operational routing system.
